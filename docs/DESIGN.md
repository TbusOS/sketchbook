# sketchbook 设计说明

> 本文件讲「做成什么样、为什么这么做」。进度和下一步在 [`PLAN.md`](PLAN.md),
> 怎么在本机跑起来在 [`DEVELOP.md`](DEVELOP.md)。

## 1 要解决什么问题

TbusOS 名下有 45 个自己写的公开仓库(2026-10-10 用 `gh repo list TbusOS` 数的,不含 fork)。
想把其中值得看的那些放在一个地方:

- **转发方便**:发一个链接,对方就能看到全部项目,点一下进任何一个仓库的首页。
- **拿到关注**:GitHub 主页现在是空模板,访客进来什么都看不到;每个仓库各自孤立,
  看了一个不知道还有别的。

成功的标准:陌生人打开 README 或网页,30 秒内知道这里有哪几类东西、哪几个最值得点开;
新开一个公开仓库后不用手动改任何东西,它第二天就会出现在列表里。

## 2 收什么、不收什么

规则写死在代码里(`scripts/lib/model.mjs`),每天按同一条规则重算:

| 条件 | 结果 | 为什么 |
|---|---|---|
| 不是公开仓、是 fork、不属于 TbusOS | 不出现 | 只收自己写的 |
| 在 `catalog.yaml` 的 `exclude` 里 | 不出现 | 占位仓、测试仓、旧博客,每条写了原因 |
| 带 topic `sandbox` | 不出现 | 仓库作者本来就用这个 topic 标测试仓 |
| 带 topic `status-archive` 或在 `archive` 里 | 「早期作品」区,默认折叠 | 内容完整但不再维护 |
| 在 `repos` 里 | 进它所在的组 | 手写的一句话介绍 |
| 都不是 | 「新上架」一栏,用 GitHub 上的描述 | 新仓库不会被漏掉;同时提醒补一句介绍 |

2026-10-10 的结果:收录 33 个(6 组)、早期作品 1 个、不收 11 个。名单见 `catalog.yaml`。

**首屏精选 6 个**:sky-skills、android-llm-bridge、ai-doc、whetstone、engram、flowsight。
按提交量和有没有在线演示挑的;改 `catalog.yaml` 的 `featured` 就能换。

**不显示 star 数,直到它超过 10**(`star_threshold`)。现在大部分仓库是 0–2 星,
卡片上写着「★0」会让人觉得没人用。先显示提交数和最近更新时间,这两个数如实反映仓库在不在动。

## 3 两个出口:README 和网页

| | GitHub 上的 README | 网页 `doc.tbusos.com/sketchbook/` |
|---|---|---|
| 谁会看到 | 从 GitHub 搜索、主页、别人 star 列表点进来的人 | 收到转发链接的人 |
| 能做什么 | 只能放 markdown 和图片,不能跑脚本 | 筛选、搜索、中英切换、深浅切换、逐笔画出来的动画 |
| 语言 | `README.md` 英文,`README_zh.md` 中文 | 一页,右上角切换 |

两边内容来自同一份数据,由同一个脚本生成,不会一边改了另一边没改。

### 3.1 README 的版面

1. 横幅:出图模型画的桌面场景(一本摊开的速写本、机器人、女孩),
   代码在速写本空白的两页上写标题、画 6 个小图标,一笔一笔画出来。
2. 一行数字:项目数 · 总提交数 · 每天更新;链接到网页版和另一种语言。
3. 精选:6 张卡片,两列。每张 = 一张配图 + 仓库名 + 一句不超过 8 个词的短句 + 语言和提交数。
4. 全部项目:6 组,每组一个小标题、一句说明、一张表(名称 · 做什么 · 状态 · 演示)。
5. 早期作品(折叠)、新上架(有的话)。
6. 「这份列表怎么来的」:数据从哪来、多久更新、怎么加一个仓库。

**卡片上只放短句,详细介绍放表格里。** 原因:手机上 GitHub 会把整张图缩小,
图里 13px 的字会缩到 5px 左右看不清;表格是真文字,手机上照样能读。

### 3.2 网页的版面

首屏横幅(和 README 同一张,但动画更完整)→ 数字 → 精选 6 张大卡(滚到哪张画哪张)
→ 项目地图(6 组画成 6 个圈,仓库是圈里的点,点的大小按提交数)→ 全部项目
(筛选按钮 + 搜索框 + 小卡片网格,每张小卡片配一个代码画的小图标)→ 早期作品 → 页脚。

每个仓库有自己的锚点,例如 `#android-llm-bridge`,单独推荐某一个时直接发这个链接。

## 4 画风:graphite(石墨铅笔)

来自 sky-skills 的 `graphite-design` skill,画图库拷在 `vendor/graphite/`(来源 commit 记在 `SOURCE`)。
定死的五样:暖纸底、会抖的深灰褐石墨线、少量来回涂的彩铅、手写批注(霞鹜文楷)、
按讲故事的顺序先线后色一笔一笔画出来。深色版是藏青墨纸 + 粉笔线,位图要另画一张,不能反相。

**谁来画**(graphite 的分工,本仓库照做):

| 画什么 | 谁画 | 为什么 |
|---|---|---|
| 横幅场景、6 张精选配图 | 出图模型(本机 `codex exec -m gpt-6-astra`) | 人物、木头、纸张的质感代码画不出来 |
| 横幅上的标题和小图标、卡片边框和字、33 个小图标、项目地图 | 代码(`sketch.js` + `props.js`) | 字要对,要能逐笔动画,要跟着数据变 |

出图模型不能按种子复现,所以每张图的提示词留在 `art/prompts/`,
附了哪些参考图写在 `scripts/illo.sh` 里。原始 PNG 不进仓库(在 `.cache/illo/`),
挑定的图转成 WebP 放 `art/source/`。

**颜色只给一件事**:每个组一支彩铅(`catalog.yaml` 的 `pen`),这支彩铅在图标、筛选按钮、
地图上都只代表这个组。

## 5 README 里的图为什么是 SVG,又为什么要把字体嵌进去

README 里的图片是用 `<img>` 显示的。这种方式下 SVG **不能加载任何外部文件**,
只认写在 SVG 里面的东西。所以:

- 手写体字体:每张 SVG 只嵌它自己用到的字(`subset-font` 现裁,几十个字约 7KB)。
- 配图:WebP 转成 base64 嵌进 SVG。
- 动画:CSS 动画写在 SVG 自己的 `<style>` 里。

**2026-10-10 在 GitHub 上实测过**(临时分支 `render-test`,用 playwright 打开 GitHub 页面截图):
嵌入字体生效(和指定系统字体的对照行字形明显不同)、嵌入 WebP 显示、铅笔滤镜生效、
CSS 动画在播放(相隔 0.7 秒的三张截图里线的长度不同)。

深浅色:每张图出浅、深两个文件,README 用 `<picture>` + `prefers-color-scheme` 跟着 GitHub 主题切换。

## 6 每天自动更新

`.github/workflows/refresh.yml`,每天 UTC 01:17 跑一次,也能手动触发:

1. `fetch.mjs` 用一个 GraphQL 请求拿到全部公开仓的数据,写 `data/repos.json`
   (按名字排序、固定格式,没变化时文件一字不差)。
2. `build.mjs` 生成 README、`art/` 下的 SVG、`site/`。
3. `check.mjs` 检查(见第 8 节)。
4. 有变化才提交;`site/` 发布到 GitHub Pages。
5. 有「新上架」的仓库时,开一个 issue 提醒补介绍(已经开着就不重复开)。

**为什么 README 里不写「3 天前更新」**:相对时间每天都变,会导致每天都有一次提交。
README 写「2026-10」这样的年月;网页在浏览器里按访问时的日期算相对时间。

**拉取失败时**:`fetch.mjs` 非零退出,不覆盖旧的 `repos.json`,这一天不提交、不发布,
Actions 页面上标红。旧数据继续在线,不会出现半截的列表。

## 7 GitHub 主页 README(`TbusOS/TbusOS`)

现在是 GitHub 自动生成的空模板。换成:横幅 + 一句话 + 6 个精选的小卡片 + 「看全部 33 个项目」。
图片直接引用 sketchbook 网页上的文件(绝对地址),所以 star 数、提交数更新时主页跟着变,
**主页仓库本身不用每天提交**,也就不需要给 Actions 配跨仓库的写权限。
主页 README 的源在本仓库 `profile/README.md`,由 `build.mjs` 生成,手动拷过去(见 PLAN)。

## 8 检查(`npm run check` / `npm test`)

| 检查 | 防什么 |
|---|---|
| 每个公开的自有仓都被归到「收录 / 早期 / 不收 / 新上架」之一 | 规则写漏导致仓库凭空消失 |
| `catalog.yaml` 里每个名字在 GitHub 上真的存在 | 改名后卡片指向 404 |
| README 引用的每张图都存在,链接都是 `https://github.com/TbusOS/...` 或网页地址 | 断图、断链 |
| 每张 SVG 用到的字都在它嵌入的字体里 | 手写体里混进系统字体 |
| 生成物和源一致(`build.mjs --check`) | 有人手改了生成的文件 |
| 网页跑 sky-skills 的 `check_objective.mjs`(本机,不在 Actions 里) | 对比度、横向滚动、手机上字太小、关掉动画后内容缺失 |

## 9 没做的和为什么

- **各成员仓库 README 底部加「看全部项目」**:2026-10-10 user 定为下一步,
  等汇总仓上线、地址确定后统一加,避免地址改了要再改 33 个仓库。
- **仓库 Social preview 图、主页置顶 6 个仓库**:GitHub 没有对应接口,只能在网页上手动做。
  图已生成在 `art/social-preview.png`。
- **star 历史曲线**:要依赖第三方服务,先不做。
